Django Admin as the control plane

Every piece of portfolio content, including the four data science and ML case studies, is a Django model registered in the admin. Edit a row and the site updates on the next request. No template or code change is needed.

Admin workflow for a case study

  1. Open /admin/ and sign in with the staff account.
  2. Choose Projects and open a case study (for example Credit Risk Analysis & Scoring System).
  3. Edit tags, description, challenge, solution, business_impact, or reorder and hide it with order / is_active directly from the list view.
  4. Save. The ORM writes the row; the page shows it on the next request.

On Vercel the filesystem is read-only, so edits only persist when DATABASE_URL points to a hosted MySQL database.

GitHub → Vercel with automated migrations

Every push to the tracked branch triggers a Vercel build. The build command applies pending migrations and refreshes the admin account before the new version goes live, so schema changes ship with the code.

  1. 1

    Push to GitHub

    Commit code and the migration file, then push to the branch Vercel tracks.

    git add .
git commit -m "Describe the change"
git push origin main
  2. 2

    Vercel imports the repo

    Vercel detects Django from manage.py ("framework": "django" in vercel.json) and serves portfolio_project/wsgi.py as the serverless entry point.

  3. 3

    Install dependencies

    requirements.txt pins Django>=5.2,<5.3 and PyMySQL>=1.1.1 (the MySQL driver).

  4. 4

    Run the build command

    Defined as buildCommand in vercel.json:

    python manage.py migrate --noinput && python manage.py ensure_superuser && python manage.py collectstatic --noinput --clear
    • migrate --noinput applies every pending migration to the database in DATABASE_URL.
    • ensure_superuser creates or updates the admin account from the DJANGO_SUPERUSER_* variables.
    • collectstatic gathers assets into staticfiles_build/static.
  5. 5

    Deploy

    Settings detect IS_VERCEL and switch sessions to signed cookies; DEBUG is read from the environment and should be False.

  6. 6

    Run against MySQL

    Admin writes go to the hosted database over SSL (MYSQL_SSL_MODE). With no DATABASE_URL the project falls back to SQLite, which is read-only once deployed.

Shipping a model change

python manage.py makemigrations portfolio
python manage.py migrate        # test locally on SQLite
git add portfolio/migrations
git commit -m "Add <change>"
git push origin main            # Vercel build runs migrate --noinput

Commit the migration file. The build only runs migrate; it never runs makemigrations.

portfolio/urls.py ends with re_path(r"^.*$", views.error_404), which matches every path. Any API include must be registered before it, or /api/... will return the 404 page.

Credit Risk Analysis & Scoring System

Python, MySQL, scikit-learn, Power BI

  • 5 MySQL tables
  • Logistic regression
  • 4+ engineered features
  • 10+ validation rules
  • 100% rejection logging
  • Est. 30-40% fewer scoring errors
  1. IngestLoan application data is read from five MySQL tables.
  2. Validate10+ validation rules run in an automated, daemon-based workflow; failures go to a rejection log (100% logged).
  3. Engineer4+ business features are derived for each application.
  4. ScoreLogistic regression produces an automated risk band; results are written back in real time.
  5. ReportRisk outcomes are surfaced in Power BI.
